# Join algorithm milestone: independent evaluator checks

Owner: evaluator specialist. Authorized scope: join algorithm selection only; no optimizer source imports, optimizer edits, Git operations, shared-helper edits or delegation.

Standalone tests: `tests/evaluator/test_join_optimizer.py`. The default evaluator corpus remains 26 cases/70 execution pairs. These tests invoke the actual optimizer executable with file arguments and a schema generated by MiniVM; they execute both original and emitted programs using MiniVM and compare full position-pair sequences, result width and error status. The source check permits replacing only a join opcode while preserving all operands, flags and unrelated instructions, as required by this milestone.

Coverage includes:

- Tiny numeric join where nested-loop costs less; larger numeric join where hashing costs less.
- Asymmetric long/short string keys where hashing costs more despite moderate row counts; larger similarly sized strings where hashing costs less.
- NULL, NULLEQ, duplicate multiplicity, empty sides, NULL-only keys, exact INT/NUM comparison with different scales and a one-unit difference at decimal scale28.
- Derived INT values beyond the NUM conversion range, including matching wide INT values and INT/NUM comparisons that must not coerce into overflowing NUM arithmetic.
- Numeric overflow and heterogeneous-key comparison errors, including alternative data for which the original succeeds.
- Join destinations aliasing source registers, both join destinations identical, reassigned LOAD and IOTA sources, mixed-case opcodes, tabs and NULLEQ preservation.
- A frozen schema chosen from a larger dataset followed by smaller/empty/duplicate/NULL datasets; frozen zero-row estimates followed by nonempty execution.
- Deliberately defective optimizer executables dropping NULLEQ or swapping output position columns. Oracle expectations come from original MiniVM execution.

## Confirmed evaluator stderr false rejection and narrow fix

Before changing code, the evaluator specialist reproduced this valid external optimizer: `sys.stderr.write('x'*300000); sys.stdout.write(open(sys.argv[1]).read())`. Evaluating baseline `bag_rows` incorrectly raised `Defect('stderr exceeded byte limit')`, with a temporary witness. The assignment constrains stdout program size and execution time, but gives no stderr diagnostic-byte restriction.

Coordinator authorized a separate harness fix: retain only the bounded stderr prefix while continuing to drain/discard further diagnostics under the existing timeout and overall deadline. Stdout beyond4MiB still terminates the subprocess, justified by MiniVM's program-size limit. Added actual external noisy-identity acceptance; changed the stderr bound unit check to require successful completion and bounded capture. Existing stdout-flood rejection and timeout tests remain. No other evaluator behavior or default corpus changed. Final post-fix tests also include the coordinator's separate LF-only optimizer lexer fix for the reviewer's Unicode-literal finding.
